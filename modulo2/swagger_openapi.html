Swagger y OpenAPI
El Contrato de tu API

La documentación es el contrato de tu API: el frontend no lee tu código en Node, lee la página /api-docs. Swagger UI te permite además probar cada endpoint con un botón ("Try it out").

Paso 1

Configuración Inicial

El ecosistema se divide en dos: OpenAPI es el formato estándar (JSON/YAML) que describe la API. Swagger son las herramientas que utilizamos para generarlo y pintarlo visualmente.

1. Instalación de paquetes

Terminal
npm install swagger-jsdoc swagger-ui-express

swagger-jsdoc junta los comentarios de tus rutas en un objeto JSON estándar.
swagger-ui-express pinta ese objeto en una página web interactiva (el famoso /api-docs).

2. Configurar `config/swagger.js`

JavaScript
const swaggerJsdoc = require('swagger-jsdoc');
const path = require('path');

const options = {
  definition: {
    openapi: '3.0.0',
    info: {
      title: 'CineData API',
      version: '1.0.0',
      description: 'API del lab cinedata: películas, usuarios y reseñas'
    },
    servers: [
      { url: 'http://localhost:3000' }
    ],
  },
  // IMPORTANTE: Ruta a los archivos donde están tus comentarios @openapi
  apis: [path.join(__dirname, '../routes/*.js')]
};

module.exports = swaggerJsdoc(options);

3. Montar la ruta en `server.js`

JavaScript
const swaggerUi = require('swagger-ui-express');
const swaggerSpec = require('./config/swagger');

// Montar ANTES del middleware de "Ruta no encontrada"
app.use('/api-docs', swaggerUi.serve, swaggerUi.setup(swaggerSpec));
app.get('/api-docs.json', (req, res) => res.json(swaggerSpec));
Paso 2

Componentes y Schemas

En lugar de repetir la estructura de una Película o un Error en cada ruta, los definimos una sola vez en el bloque components (dentro de swagger.js) y los referenciamos usando $ref. Se describe lo que viaja por HTTP, no lo que hay exactamente en Mongo.

Ejemplo: Añadiendo Schemas al definition

JavaScript (config/swagger.js)
definition: {
  openapi: '3.0.0',
  /* ... info y servers ... */
  components: {
    parameters: {
      Id: {
        in: 'path',
        name: 'id',
        required: true,
        schema: { type: 'string' },
        description: 'ID autogenerado por MongoDB'
      }
    },
    schemas: {
      Error: {
        type: 'object',
        properties: {
          error: { type: 'string', example: 'Película no encontrada' }
        }
      },
      Pelicula: {
        type: 'object',
        properties: {
          id: { type: 'string', example: '6ad8f53...' },
          titulo: { type: 'string', example: 'Blade Runner 2049' },
          anio: { type: 'integer', example: 2017 },
          duracion: { type: 'string', example: '2h 44min' } // ¡Ojo! Lo que envía el toJSON
        }
      },
      PeliculaEntrada: {
        type: 'object',
        required: ['titulo', 'anio'], // Campos obligatorios para el POST/PUT
        properties: {
          titulo: { type: 'string' },
          anio: { type: 'integer' }
        }
      }
    }
  }
}
Paso 3

Documentar Rutas (Ejemplos YAML)

Encima de cada ruta en tus archivos de controladores/rutas, añadimos un comentario multilínea empezando por /** @openapi. El contenido interior es YAML, donde la sangría (2 espacios) es la sintaxis.

GET Listar todos (Con Array)

YAML
/**
 * @openapi
 * /peliculas:
 *   get:
 *     tags: [Películas]
 *     summary: Lista las películas ordenadas por nota
 *     responses:
 *       200:
 *         description: Catálogo completo
 *         content:
 *           application/json:
 *             schema:
 *               type: array
 *               items:
 *                 $ref: '#/components/schemas/Pelicula'
 */
router.get('/', obtenerTodas);

POST Crear recurso (Con Body)

YAML
/**
 * @openapi
 * /peliculas:
 *   post:
 *     tags: [Películas]
 *     summary: Crea una película
 *     requestBody:
 *       required: true
 *       content:
 *         application/json:
 *           schema:
 *             $ref: '#/components/schemas/PeliculaEntrada'
 *     responses:
 *       201:
 *         description: Película creada con éxito
 *         content:
 *           application/json:
 *             schema:
 *               $ref: '#/components/schemas/Pelicula'
 *       400:
 *         description: Error de validación (ej. falta título)
 *         content:
 *           application/json:
 *             schema:
 *               $ref: '#/components/schemas/Error'
 */
router.post('/', crear);

DELETE Borrar recurso (Con Parámetro Path)

Fíjate en cómo reutilizamos el parámetro Id configurado en el Paso 2.

YAML
/**
 * @openapi
 * /peliculas/{id}:
 *   delete:
 *     tags: [Películas]
 *     summary: Borra una película
 *     parameters:
 *       - $ref: '#/components/parameters/Id'
 *     responses:
 *       204:
 *         description: Película eliminada (No Content)
 *       400:
 *         description: Formato de ID inválido
 *       404:
 *         description: Película no encontrada
 */
router.delete('/:id', validarId, borrar);
La Regla de Oro La documentación dice exactamente lo mismo que el código. Si tu código devuelve un 404 en el if (!usuario), debe estar documentado. Si devuelve un 204 en el DELETE, debe estar documentado. Si devuelves un código no documentado, el contrato miente.
Troubleshooting

Errores comunes en Swagger

swagger-jsdoc no rompe el servidor, pero si encuentra un error de sintaxis en el YAML, escribirá el error en la terminal y se saltará ese bloque.

Mensaje en TerminalCausa / Solución
All collection items must start at the same column Sangría incorrecta: Debes usar exactamente dos espacios por nivel. Nunca uses tabuladores.
Nested mappings are not allowed Dos puntos conflictivos: Tienes un : dentro de tu texto (ej. en una description). Solución: pon todo el texto entre comillas dobles "Texto con: dos puntos".
Could not resolve reference Ruta $ref incorrecta: El nombre del componente no coincide. Revisa que sea exactamente #/components/schemas/TuModelo respetando mayúsculas.
No sale ninguna ruta en la UI En swagger.js, el campo apis está mal escrito o usaste /* en lugar de /** para rutas anidadas.
/api-docs da error 404 Colocaste app.use('/api-docs') por debajo del middleware de "Ruta no encontrada" en server.js.
Failed to fetch (En el Try it out) El servidor backend está apagado, o el array servers de tu swagger.js apunta al puerto equivocado.
