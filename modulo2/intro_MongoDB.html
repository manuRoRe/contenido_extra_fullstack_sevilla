Fundamentos

¿Qué es NoSQL? El fin de la rigidez

Las bases de datos SQL exigen esquemas rígidos y escalan verticalmente, sufriendo fricción al modelar objetos anidados. NoSQL aporta una estructura flexible nativa y escalabilidad horizontal.[cite: 10]

Concepto SQL MongoDB[cite: 10]
Agrupación Tabla (columnas fijas) Colección (esquema flexible)[cite: 9, 10]

Identificador Primary Key / id INT Campo _id / ObjectId[cite: 10]

2

El Motor Oculto: JSON vs BSON[cite: 10]

Escribimos nuestro código en JSON (legible por humanos, soporta strings, numbers, booleans, arrays y objetos). Sin embargo, internamente MongoDB lo serializa a BSON (Binary JSON), lo que permite velocidades superiores y soporta tipos extendidos como `Date`, `Buffer` y `ObjectId`.[cite: 10]

🔍 El identificador ObjectId Todo documento tiene un campo _id. Si no se provee, MongoDB genera automáticamente un ObjectId único de 12 bytes (marca de tiempo + máquina + contador).[cite: 9, 10]

Consultas

La Base de la Lectura y Filtrado

Las consultas en MongoDB utilizan sintaxis JSON y operadores especializados. La estructura general es: db.coleccion.find(<filtro>, <proyección>).sort(...).limit(...)[cite: 10].

1

Caja de Herramientas: Operadores y Control de Flujo[cite: 10]

Operador Significado Ejemplo[cite: 9, 10]
$gt / $gte Mayor / Mayor o igual { nota: {$gt: 8.5 } }[cite: 9, 10]
$lt / $lte Menor / Menor o igual { duracion: {$lt: 100 } }[cite: 9, 10]
$ne Distinto de { pais: {$ne: 'EEUU' } }[cite: 9, 10]
$in Está en la lista { generos: { $in: ['Drama', 'Acción'] } }[cite: 9, 10]
$or Ramifica condiciones $or: [ {nota: 9}, {vistas: 100} ][cite: 9, 10]
$regex Búsqueda de texto flexible { titulo: { $regex: '^El' } }[cite: 10]
💡 Regla del AND implícito y Arrays Directos Las claves separadas por coma dentro de un objeto filtro se combinan con AND automáticamente. Además, para buscar un elemento dentro de un array, basta con pasar el valor directo: db.peliculas.find({ generos: 'Drama' }) encuentra todos los documentos cuyo array 'generos' contenga 'Drama'.[cite: 10]
2

Navegar Anidados: La Notación por Punto[cite: 10]

Para acceder a sub-objetos, se utiliza padre.hijo. Crítico: Las comillas dobles son obligatorias en la clave al usar el punto.[cite: 10]

MQL 
// Correcto: acceso a subcampo
db.peliculas.find({ "director.nombre": "Christopher Nolan" })[cite: 9, 10]
3

Eficiencia: Proyección y Modificadores[cite: 10]

La proyección elige qué campos devolver para ahorrar ancho de banda. Funciona con una Regla Binaria: 1 incluye, 0 excluye. Excepción: No se pueden mezclar 1s y 0s, salvo para excluir explícitamente el _id: 0.[cite: 9, 10]

MQL 
db.peliculas.find({}, { titulo: 1, nota: 1, _id: 0 })
  .sort({ nota: -1 }) // -1 Descendente, 1 Ascendente
  .skip(5)            // Salta los 5 primeros (Paginación)
  .limit(3)           // Devuelve solo 3[cite: 9, 10]
Operaciones de Escritura

Mutación (I y II): Inserción, Actualización y Borrado

1

Actualizar con Bisturí: Operadores de Mutación[cite: 10]

Los comandos updateOne y updateMany requieren un filtro y un modificador específico para no sobreescribir todo el documento accidentalmente.[cite: 9, 10]

  • $set: Cambia o crea el valor de un campo.[cite: 10]
  • $unset: Elimina un campo por completo.[cite: 10]
  • $inc: Incrementa (o decrementa) un numérico (ej. { $inc: { nota: 0.1 } }).[cite: 9, 10]
  • $push / $pull: Añade / quita elementos de un array.[cite: 9, 10]
  • $addToSet: Añade a un array solo si no existía previamente.[cite: 10]
2

Destruir Datos: El peligro de deleteMany[cite: 10]

deleteOne({ ... }) elimina la primera coincidencia. Sin embargo, deleteMany({}) sin filtros destruye la colección entera.[cite: 9, 10]

⚠️ Práctica Profesional Obligatoria No hay papelera de reciclaje ni confirmación en MQL. Ejecuta siempre un find() con el mismo filtro exacto para verificar los documentos antes de disparar un deleteMany().[cite: 10]
Modelado Avanzado

Estrategia de Modelado y Agregaciones[cite: 10]

1

¿Embeber o Referenciar?[cite: 9, 10]

Estrategia Qué es y Cuándo usarla Pros / Contras[cite: 10]
Anidar (Embedding)[cite: 10] Meter datos relacionados dentro del padre. Uso: Lectura conjunta, cuando el hijo no tiene vida propia (Ej: un pedido y sus líneas).[cite: 10] ✅ Lectura ultrarrápida.
❌ Riesgo de datos duplicados y límite de 16MB.[cite: 10]
Referenciar[cite: 10] Guardar el ObjectId del documento relacionado. Uso: Datos gigantes o que cambian frecuentemente (Ej: usuarios y reseñas).[cite: 9, 10] ✅ Cero duplicidad de datos.
❌ Requiere 2 consultas o usar $lookup.[cite: 10]
2

Arquitectura Analítica: Aggregation Pipeline[cite: 10]

Una secuencia de etapas que actúan como una cadena de montaje transformando documentos progresivamente, superando las limitaciones de find().[cite: 10]

  • $match: Filtra documentos (El WHERE de SQL).[cite: 10]
  • $group: Agrupa y realiza cálculos matemáticos (Ej: { $sum: 1 }).[cite: 10]
  • $unwind: "Explota" un array, creando un documento individual por cada elemento.[cite: 10]
  • $lookup: Ejecuta un LEFT JOIN con otra colección usando un campo local y uno foráneo.[cite: 9, 10]
Resumen

Chuleta de MQL[cite: 9]

Crear[cite: 9]
insertOne({ ... }) insertMany([ ... ])

La base y colección nacen al insertar.[cite: 9]

Leer[cite: 9]
find(filtro, proyeccion) findOne(filtro)

Trae todos o solo el primero.[cite: 9]

Modificadores[cite: 9]
.sort({ nota: -1 }) .limit(3)

Ordenamiento y paginación en cadena.[cite: 9, 10]

Actualizar[cite: 9]
updateOne(filtro, modificador) updateMany(filtro, modificador)

Usar siempre con $set,$push, etc.[cite: 9, 10]

Borrar[cite: 9]
deleteOne(filtro) deleteMany(filtro)

Cuidado: deleteMany({}) borra todo.[cite: 9, 10]

Relaciones[cite: 9]
{ _id: ObjectId(...) } $lookup

Embeber objetos o referenciar IDs.[cite: 9, 10]
